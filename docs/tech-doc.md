# 摘要（0.5 页）

本项目是一个面向编程初学者的代码学习助手，帮助学习者在"看不懂、找不到错、不知道练什么"三个环节获得即时帮助。

与直接向通用大模型提问不同，本项目把工作拆成两部分：**确定性的结构化工作在程序里完成**（语法识别、报错堆栈解析、错误类型匹配、语言检测），**自然语言生成交给大模型**（讲解、改法、练习）。模型的输出必须落在程序给定的结构里，不许自由发挥。

完整的技术栈为 Next.js 16 + TypeScript + React 19，通过服务端 Route Handler 调用智谱 GLM 模型并转发为 SSE 流式响应；服务端密钥不下发浏览器，按访问 IP 做额度限流，错误信息统一脱敏。

│                      ▼                                 │

## 4.2 前后端职责边界

| 层 | 负责 | 不负责 |
|---|---|---|
| 浏览器 | 交互、状态、历史、渲染、结构化预处理 | **任何密钥** |
| 服务端 | 入参校验、限流、密钥持有、上游调用、流式转写、错误脱敏 | 业务文案、用户数据存储 |

**设计原则：浏览器是"不可信客户端"。** 所有可能被滥用的能力（密钥、外部请求、限流）都必须在服务端边界内。

## 4.3 关键设计一：把结构化工作从模型手里拿走

这是本项目架构上最重要的一条约束。

| 工作 | 交给谁 | 为什么 |
|---|---|---|
| 判断代码是什么语言 | **程序**（`languageDetect.ts`，按扩展名与关键字） | 确定性工作，模型判断反而会错 |
| 从 Java 堆栈里抽出异常类型/消息/行号 | **程序**（`errorParser.ts`，正则 + 模式匹配） | 行号必须准确，不能由模型"估" |
| 匹配常见错误类型与处理方案 | **程序**（`errorKnowledge.ts`，本地知识库索引） | 固定知识，不需要每次生成 |
| 解释这个错误是什么意思、怎么改 | **模型** | 需要自然语言与上下文 |

**一句话：能用代码算出来的，不给模型机会。**

**这条约束的效果**：模型的输出范围被限制在"解释与建议"，它没有机会把行号算错、把语言认错、把错误类型编错。

**【你填 4–6 行：写你当初为什么这么分。参考方向：你发现让模型解析堆栈时行号经常不准，所以改成程序解析、模型只解释。把那次发现写具体。】**

## 4.4 关键设计二：流式响应

模型回答较长，等完整结果再返回会让用户干等十几秒。

实现方式：服务端拿到上游的 `ReadableStream`，逐行解析 `data:` 事件，抽出 `delta.content`，重新封装成自己的 SSE 格式推给前端；遇到 `[DONE]` 关闭连接。

**为什么要重新封装而不是直接透传**：透传会把上游的原始结构、模型名、可能的错误细节一起送到浏览器。重新封装后，浏览器只收到 `{"content": "..."}`，**上游信息一律不外泄**。

## 4.5 关键设计三：安全边界

这一节建议单独展开——**它同时是"架构设计"和"意图控制"的证据**。

| 安全要求 | 实现 |
|---|---|
| 密钥不下发浏览器 | 只从服务端 `process.env` 读取；前端全程无密钥字段 |
| 错误信息脱敏 | 任何返回给浏览器的错误串中，若含密钥则替换为 `***` |
| 滥用防护 | 走服务端额度时按 IP 限流（10 次/分钟、100 次/天） |
| 自定义接口地址 | **仅在使用自带密钥时允许**；且必须 https + 域名白名单 |
| 入参校验 | messages 条数上限、单条长度上限、role/content 类型校验 |

## 5.1 我的提问结构

我固定使用四段式，缺哪段就在哪段出问题：

| 段 | 作用 | 漏了会怎样 |
|---|---|---|
| **目标** | 一句话说清要什么，具体到可验证 | 拿到一个"通用版"，还得自己改 |
| **约束** | 技术栈、路径、**哪些文件不能动** | 模型看不到我的目录，会覆盖或重构 |
| **验收** | 什么算做完 | 自己也没想清楚，交付后无从判断 |

# 7. 工程权衡与局限（3 页）

> 主动写局限是加分项。被问出来才写是减分项。

| 项 | 现状 | 为什么这样取舍 |
|---|---|---|
| **限流** | 计数器存于服务进程内存 | 本地与单实例自托管严格有效；**部署到 serverless 后各实例独立、冷启动重置，等于尽力而为**。严格全局限制需接 KV/Redis，本期未实现 |
| **自定义接口地址** | 仅限自带密钥 + https + 域名白名单 | 开放性让位于安全性。完全放开会造成凭据外泄与 SSRF |
| **对话历史** | 存 `localStorage`，不上传 | 隐私优先。代价：换设备/清缓存即丢失 |
| **数据持久化** | 无服务端存储、无用户系统 | 减少攻击面；代价：无法跨设备同步 |
| **模型** | 默认使用免费模型 | 成本为零；代价：高峰期限流、复杂任务质量一般 |
| **错误知识库** | 内置静态数据（288 行） | 覆盖常见类型；代价：罕见错误匹配不到，会回落到模型解释 |

# 写作纪律（三条）

1. **凡是"我"的判断，必须写成第一人称的具体决定**，不要写"本系统采用了……"。规则要的是你的意图，不是系统说明书。
2. **数字必须真实。** 没测过的不要写"提升 30%"。写"未实测"也比编一个强，因为评委可能追问。
3. **主动写局限。** 第 7 章写满，比在别的章节吹三页强。
