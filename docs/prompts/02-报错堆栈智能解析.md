# Prompt 链 02：报错堆栈智能解析

> 用途：在 Trae 中复制以下对话，形成"需求 → AI 生成 → 验证 → 迭代"的完整 Prompt 链。
> 这是本作品最有特色的功能，重点展示 AI 协同与意图控制能力。

## 项目背景（首次对话必发）

```
项目：AI 代码学习助手（Next.js + React + TypeScript + Tailwind）
路径：D:\Projects\AI-Code-Teacher
现有结构：
- src/app/page.tsx — 主页面，左侧输入区+右侧AI回答
- src/app/api/chat/route.ts — 智谱AI流式接口
- src/lib/modes.ts — 4种辅导模式
- src/components/CodeEditor.tsx — Monaco编辑器

当前"找 Bug"模式只能把用户输入的报错原文直接发给AI。
我想做一个增强：用户粘贴 Java 异常堆栈时，前端自动解析出异常类型、错误消息、出错文件和行号，
生成面向零基础学生的通俗摘要，然后把摘要+原文一起发给AI，让AI回答更精准。
```

---

## 第一轮：提出需求

```
请帮我实现"Java 报错堆栈智能解析"功能：

1. 新建 src/lib/errorParser.ts，实现一个 parseJavaError(input: string) 函数：
   - 识别输入是否是 Java 异常堆栈（包含 Exception/Error 或 "at " 堆栈行）
   - 提取异常类型（如 java.lang.ArrayIndexOutOfBoundsException）和简短类名
   - 提取错误消息（异常类型后面的冒号内容）
   - 提取出错位置：从 "at 包名.类名.方法(文件:行号)" 中解析文件名和行号
   - 提取线程名（"Exception in thread xxx"）
   - 生成中文摘要：异常类型 + 通俗解释 + 错误信息 + 出错位置 + 线程

2. 内置一个常见 Java 异常的通俗解释表（至少 15 种），比如：
   - ArrayIndexOutOfBoundsException → "数组下标越界：访问了数组不存在的位置"
   - NullPointerException → "空指针异常：对一个值为null的对象调用了方法"
   - NumberFormatException → "数字格式错误：把非数字字符串转成了数字"
   等等，要覆盖大一学生最常遇到的异常。

3. 在 page.tsx 中集成：
   - 用户输入时，如果 looksLikeErrorStack(input) 为 true，在编辑器上方显示一个琥珀色提示条，展示解析结果
   - 发送时，把解析摘要和原始报错一起组装成最终内容发给AI
   - 提示条要显示：异常类型（带通俗解释）、错误信息、出错位置（文件+行号）

4. 要求：
   - 纯前端解析，不依赖额外库
   - TypeScript 类型完整
   - 解析失败时不影响正常发送（降级为原文发送）
   - 提示条样式要和整体深色主题协调
```

## 第二轮：验证与追问（AI 生成后发）

```
检查一下：
1. parseJavaError 是否能正确解析这种格式：
   Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
       at com.example.Main.main(Main.java:12)
2. 通俗解释表是否覆盖了大一学生最常见的异常？至少要有：
   ArrayIndexOutOfBoundsException、NullPointerException、NumberFormatException、
   ArithmeticException、ClassCastException、IllegalArgumentException、
   IndexOutOfBoundsException、OutOfMemoryError、StackOverflowError、
   FileNotFoundException、IOException、InputMismatchException
3. 提示条是否只在检测到报错时才显示？正常代码输入时不应该显示。
4. 发送给AI的内容格式是否清晰？要让AI能区分"解析摘要"和"原始报错"。
5. 如果用户输入的不是Java报错（比如是Python报错），是否会误触发？

有问题请修正。
```

## 第三轮：迭代优化

```
我测试了一下，有几个问题需要优化：

1. 有些异常堆栈第一行不是"Exception in thread"，而是直接"java.lang.XXXException: message"，
   你的解析器能处理吗？请确保两种格式都能识别。

2. 出错位置可能有多个"at"行，应该取第一个（最接近用户代码的），
   而不是取JDK内部的方法。请优化：优先取包含用户项目包名的行，
   如果没有，取第一个"at"行。

3. 提示条的样式再优化一下：
   - 用琥珀色/黄色边框和背景，和"警告"语义一致
   - 异常类型用等宽字体显示
   - 通俗解释用稍小的字号，颜色稍淡
   - 整体不要太高，控制在 3-4 行

4. 在发送给AI的内容开头，加上一句明确的指令：
   "请基于以上解析结果，用通俗语言解释这个错误的原因和修复方法。"
```
