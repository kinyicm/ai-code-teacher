# 离线错误知识库：四种常见代码错误类型

## Context（背景）

当前应用所有回答都依赖智谱 AI API（`/api/chat`），断网或接口不可用时无法获得任何辅导。用户希望把**四种常见代码错误类型**（语法错误 / 编译错误 / 运行时错误 / 逻辑错误）的知识库内置到前端，使「找 Bug」模式在**无网络**情况下也能识别并解答这四类错误，实现离线操作。

目标结果：
1. 找 Bug 模式提交的内容若命中内置知识库 → 本地直接生成解答（不调 API），标注「离线解答 · 未调用 AI」。
2. 模式栏新增「📚 错误手册」按钮 → 弹窗展示 4 类错误卡片，点击可把示例代码填入输入区，供学生离线练习。
3. 离线解答与普通消息一样持久化到 localStorage，历史记录语言筛选兼容。

## 关键假设

「四种类型的代码错误」按编程入门教学中的标准四分类实现：**语法错误 / 编译错误 / 运行时错误 / 逻辑错误**。（若用户另有所指，可在批准前指出。）

## 实现步骤

### Step 1 新建 `src/lib/errorKnowledge.ts`（核心数据 + 检测）

类型定义：

```ts
export type ErrorTypeId = "syntax" | "compile" | "runtime" | "logic";

export interface ErrorKnowledge {
  id: ErrorTypeId;
  name: string;                 // 中文名，如「运行时错误」
  icon: string;                 // emoji 图标
  plainExplanation: string;     // 零基础通俗解释
  scenarios: string[];          // 常见触发场景
  detectRules: { lang?: LangId; re: RegExp; reason: string }[]; // 检测规则
  debugSteps: string[];         // 排查思路步骤
  fixExample: { lang: LangId; code: string };  // 典型修复示例
  practiceHint?: string;        // 练习提示
}

export function classifyError(input: string):
  { type: ErrorTypeId; reason: string; lang: LangId | null } | null;

export function buildOfflineAnswer(k: ErrorKnowledge, reason: string, lang: LangId | null): string;
```

检测逻辑（`classifyError`）：
- **运行时错误**：复用 `parseJavaError`（`src/lib/errorParser.ts`），Java 异常堆栈命中即归运行时。
- **编译错误**：强关键词，如 `cannot find symbol`、`undefined reference`、`undeclared identifier`、`unexpected token`、`SyntaxError`、`CompilationError` 等。
- **语法错误**：弱规则（括号/大括号不平衡、语言特征符号缺失），要求「命中 ≥ 2 条规则或含代码围栏」才判定，避免误报。
- **逻辑错误**：弱规则（`while(true)` 无 break、`i <= arr.length` 越界、`if (x = 1)` 赋值误作比较），同样要求多规则命中。
- **防误报**：输入长度 ≥ 10、代码符号密度达标、纯中文描述不判定；正则全部 `\b` 锚定。

`buildOfflineAnswer`：拼 Markdown（类型名+icon 标题、通俗解释、场景、排查步骤、`` ```lang `` 修复示例、练习提示、末尾「离线解答 · 未调用 AI」）。含代码围栏 → 历史语言筛选天然兼容。

### Step 2 集成 `src/app/page.tsx`

- 新增 `appendOfflineReply(userBubbleContent, result)`：不复用 `runTurn`（其硬编码 API 流式），直接用两次 `setMessages` 追加「用户气泡 + 完整 assistant 气泡」，`mode` 沿用当前值，不涉及 `isThinking`/`AbortController`。
- `handleSubmit` 头部插入离线优先分支（仅找 Bug 模式生效）：

```ts
if (mode === "debug") {
  const off = classifyError(content);
  if (off) { setInput(""); appendOfflineReply(content, off); return; }
}
```

未命中继续走原「Java 堆栈增强 + runTurn API」流程，两者共存互不影响。
- 新增状态 `const [handbookOpen, setHandbookOpen] = useState(false)`；模式栏（L423 附近，分析薄弱点按钮旁）加「📚 错误手册」按钮（emerald 色区分）。

### Step 3 新建 `src/components/ErrorHandbook.tsx`

- Props：`{ onClose: () => void; onPick: (lang: LangId, code: string) => void }`。
- 复刻 HistoryPanel 弹窗风格（`fixed inset-0 z-50 bg-black/60`、`max-w-2xl`、Esc/遮罩关闭）。
- 4 张卡片（2×2 grid）：icon + 名称 + 通俗解释一句 + 修复示例缩略；点击调 `onPick(fixExample.lang, fixExample.code)`。
- 页面侧 `onPick`：`setInput(code); setLanguage(lang); setHandbookOpen(false);`——CodeEditor 受 `value={input}` 控制，改 state 即填入，无需动 CodeEditor。

### Step 4 持久化与兼容

离线解答作为正常 `ChatMessage` 入 `messages`，现有 localStorage effect 自动保存，无需改动 HistoryPanel/语言筛选。

## 验证方案

1. `node node_modules/typescript/bin/tsc --noEmit`（沙箱下 PowerShell 禁用脚本，用 node 直跑）通过。
2. 浏览器（断网/DevTools Offline）分别粘贴四类样例（Java 堆栈、`cannot find symbol`、`SyntaxError: Unexpected token`、`while(true)` 无 break），确认出现「离线解答 · 未调用 AI」气泡且 **Network 无 `/api/chat` 请求**。
3. 在线时输入普通描述「我的 for 循环报错了」——不误判，仍走 API。
4. 打开「错误手册」弹窗，点击卡片 → 输入区自动填入示例代码。
5. 历史记录里离线解答按语言筛选可见。
